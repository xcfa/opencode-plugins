# opencode-plugins

Плагины для [OpenCode](https://opencode.ai) 2.x (Promise API `@opencode/plugin`, проверялись по исходникам `v2.0.21`).

| Плагин | Что делает |
|---|---|
| [`user-content`](user-content/index.js) | Модель сама решает, кому адресован результат инструмента: себе или пользователю |

## Подключение

Плагин — это каталог. В конфиге OpenCode укажите путь к нему: относительный (от каталога конфига) или абсолютный.

```json
{
  "plugin": ["./plugins/user-content"]
}
```

После запуска в логе OpenCode должна появиться строка `loading plugin` с путём к плагину.

## user-content

Каждому инструменту добавляется необязательный аргумент `audience`:

- `"assistant"` (по умолчанию) — результат, как обычно, возвращается модели;
- `"user"` — файлы из результата (например, изображения) сохраняются для пользователя и модели не возвращаются.

Вместо файлов модель получает их пути в виде готовой Markdown-разметки и показывает пользователю те, что вставит
в итоговый ответ:

```markdown
Вот фото с моста: ![Велосипед на мосту](/home/user/.local/share/opencode/user-content/ses_…/call_…-1.jpg)
```

Чат OpenCode отрисовывает такие картинки сам: веб-интерфейс читает локальные файлы из Markdown через
`/api/fs/read`. Картинка становится обычной частью ответа, её видит любой клиент, а в контекст модели она не попадает.

Как это устроено:

- аргумент добавляется в настоящие схемы MCP-инструментов (`tool.transform`): так его видит модель, в том числе
  в сигнатурах Code Mode, и его не выбрасывает встроенный плагин `tool-input-repair`, который удаляет из аргументов
  поля, которых нет в схеме;
- в системный промпт добавляется правило: файлы, которые пользователь просит показать или прислать, запрашивать
  с `audience: "user"` и вставлять в ответ, а не давать ссылки;
- перед вызовом (`tool.hook("execute.before")`) плагин убирает `audience` из аргументов — серверам инструментов
  знать о нём не нужно — и запоминает по id вызова, что результат адресован пользователю;
- после вызова (`tool.hook("execute.after")`) файлы из результата сохраняются в каталог плагина, а модель вместо
  них получает текст с путями. В Code Mode пути дополнительно дописываются в результат `execute`: код может
  не вывести текст вложенного вызова.

Опции (в конфиге — `{ "package": "./plugins/user-content", "options": { … } }`):

| Опция | По умолчанию | Описание |
|---|---|---|
| `directory` | `~/.local/share/opencode/user-content` | Куда сохранять файлы; внутри — каталог на каждую сессию |

Типичный сценарий: модель находит фото по метаданным (или смотрит превью сама), выбирает подходящие, запрашивает их
ещё раз с `audience: "user"` — например, по id — и вставляет в ответ:

```js
for (const id of ["a1", "a5"]) await tools.immich.get_preview({ id, audience: "user" })
```

Нужно, чтобы у сервера был метод, возвращающий картинку (MCP `image`) по идентификатору.
