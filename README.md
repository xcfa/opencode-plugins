# opencode-plugins

Плагины для [OpenCode](https://opencode.ai) 2.x (Promise API `@opencode/plugin`, проверялись по исходникам `v2.0.21`).

| Плагин | Что делает |
|---|---|
| [`user-content`](user-content/index.js) | Модель сама решает, кому адресован результат инструмента: себе или пользователю |

## Подключение

Плагин — это каталог. В конфиге OpenCode укажите путь к нему: относительный (от каталога конфига) или абсолютный.

```json
{
  "plugin": ["./plugins/user-content"]
}
```

После запуска в логе OpenCode должна появиться строка `loading plugin` с путём к плагину.

## user-content

Каждому инструменту добавляется необязательный аргумент `audience`:

- `"assistant"` (по умолчанию) — результат, как обычно, возвращается модели;
- `"user"` — файлы из результата (например, изображения) показываются пользователю и в контекст модели не попадают.

Как это устроено:

- аргумент добавляется в схемы инструментов, которые видит модель (`session.hook("context")`), а для Code Mode —
  в описание `execute`;
- перед вызовом (`tool.hook("execute.before")`) плагин убирает `audience` из аргументов, так что серверам
  инструментов, в том числе MCP, знать о нём не нужно, и запоминает, какие вызовы адресованы пользователю;
- после вызова (`tool.hook("execute.after")`) файлы из `content` результата (его видит модель) переносятся
  в `metadata.user_content` (её модель не видит). Вместо файлов модель получает строку
  «N file(s) were shown to the user…»;
- `metadata` хранится в истории сессии и приходит клиентам в событии `session.tool.success`, так что показать файлы
  может любой клиент. В Code Mode файлы вложенных вызовов прикрепляются к `metadata` результата `execute`.

Типичный сценарий: модель находит фото по метаданным (или смотрит превью сама), выбирает подходящие и запрашивает их
ещё раз с `audience: "user"`, например по id:

```js
for (const id of ["a1", "a5"]) await tools.immich.get_preview({ id, audience: "user" })
```

Нужно, чтобы у сервера был метод, возвращающий картинку (MCP `image`) по идентификатору.

Пример клиента, который показывает `metadata.user_content` вместе с итоговым ответом, —
[telegram-bot](https://github.com/xcfa/telegram-bot).
